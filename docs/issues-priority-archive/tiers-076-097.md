## Tier 77 — Confirmed Apple Health step double-counting (2026-07-28)

| # | Status | Issue | Notes |
|---|--------|-------|-------|
| [#385](https://github.com/ZhannaM85/turtle-steps-to-the-goal/issues/385) | ✅ Done | Apple Health step import likely double-counts multi-source overlapping steps | Resolved via `AskUserQuestion` given no real multi-source sample export to validate a true interval-overlap merge against: best-effort per-day dominant source, not full interval merging. `AppleHealthRecord` now captures `sourceName` (parsed but previously discarded). `AppleHealthPatchBuilder` sums same-source intraday `StepCount` records same as before, but now keyed per `(date, sourceName)`; `build()` keeps only the single source with the highest total for that date and discards the rest, rather than summing across sources. A record with no `sourceName` at all (not expected in a real export) falls into its own single "unknown" bucket rather than silently merging into whichever named source is seen first. Known limitation, accepted as part of the chosen approach: a day where two sources each captured different real activity (e.g. phone left at home part of the day) could undercount rather than double-count — the safer direction of the two possible errors, and the same trade-off #368's own research already flagged for HealthKit multi-source data in general. New tests cover dominant-source selection, per-date independence, and that same-source summing is unchanged. |
